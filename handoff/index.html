후임자가 가장 먼저 잠글 결정 3건

1. 상무 직통번호 공개 방식

개인번호인지 회사 명의 업무용 번호인지 확정해야 합니다. 공개한 번호는 회수하기 어렵습니다. 공개 저장소에는 절대 기록하지 않습니다.

2. 번호 전용 화면의 장수

현재는 6장입니다. “검은 화면 한 장”을 슬라이드 06의 전체 화면 연출로 볼지, 실제 7번째 장으로 추가할지 결정해야 합니다.

3. Google PPT 마감

1차 시안 수령일, 통합 피드백일, 최종 파일 확정 시간을 Google 담당자와 캘린더로 잠가야 합니다.

수정하고 배포하는 법

저장소는 공개 상태입니다. 개인 전화번호, 내부 담당자 연락처, 미공개 조건은 로컬 전달 자료에서만 관리합니다.

1. 최신본 받고 작업 브랜치 생성

git switch main
git pull --ff-only
git switch -c agent/<작업명>

2. 원본 수정 후 Google 전달본 재생성

# final-v1/index.html 수정
node build-google.js

3. 검증 후 필요한 파일만 커밋

git diff --check
git status --short
git add -- <수정한 파일만 정확히 지정>
git commit -m "변경 내용을 설명하는 메시지"

4. 배포 확인

main 병합 후 GitHub Pages 배포가 끝나면 내부 준비본, Google 전달본, PDF 링크를 각각 열어 확인합니다. PDF는 HTML 변경 뒤 다시 생성해야 합니다.
